# M1: shipped AlignTune vs patched AlignTune vs securegrade (runs of 1–2 Nov 2026)

**Result.** With tests supplied, the patched AlignTune rewards and securegrade both pay **0** (≤ 0 for
`mbpp_reward`, which penalises) for every Gate 1 "solves nothing" exploit on all 5 tasks.
Shipped AlignTune paid **1.00** on all 5 for at least one exploit in each of its four execution
rewards. On reference solutions across all of MBPP-sanitized (427) and HumanEval (164),
all **591 supplied references passed securegrade in the recorded checks** (fenced and bare; also 164 HumanEval body-only + prompt). This is finite compatibility evidence, not a universal false-negative rate. Patched AlignTune has 0–2.5% on MBPP and 1–7% on HumanEval;
shipped has up to 19% on bare code and 100% for `code_correctness` on fenced code.

Versions: shipped = aligntune 0.1.28 from PyPI (`~/p9/at`). Patched = commit `57e9a95` +
`patches/aligntune/aligntune-57e9a95-securegrade-fixes.diff` (`~/p9/at-patched`). securegrade = this
project's `securegrade/` (stdlib only). Same trl 1.7.1 / torch 2.11.0 in both AlignTune venvs. All runs
were CPU-only in gentle mode (nice 19, 4 workers, 1 GiB per securegrade child).

What is left in the patched column, investigated:
- HumanEval, 9 tasks (1, 32, 38, 44, 50, 53, 87, 113, 151): their asserts use `check()`'s loop
  variables or helpers, so single-line asserts cannot be lifted out. securegrade runs the whole
  `check()` program on the trusted side and has no such limit.
- `mbpp_reward`, 3 more HumanEval tasks: its own format penalties (-0.02 per "```", "Example:",
  "print(") push correct fenced answers below 0.95.
- `code_correctness`, 8 tasks: dict tests carry no function name, so the first public `def` is
  taken; these references define a helper first.
- securegrade needed two fixes to reach 0: MBPP/126 names its function `sum` (the entry point may
  shadow a builtin, nothing else may), and MBPP/737/787/794 return `re.Match` (truth value only
  crosses, as an object that equals nothing).

securegrade on the exploits across all 591 tasks: no exploit reached full marks anywhere. The stub
(and fake `PASS:` printing, which also returns None) gets partial credit on 22 tasks (14 MBPP, 8
HumanEval; mean 0.013 / 0.018) and the always-equal object on 9 (truthiness asserts), because those
tests expect `None` or a falsy value. `mode="all_pass"` removes partial credit.
